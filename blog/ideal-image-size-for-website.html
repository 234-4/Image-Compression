What Is the Ideal Image Size for a Website?

Published October 27, 2026 · 5 min read

Ask ten web designers for the perfect image size and you will get ten different answers. That is because there is no single number. What works is knowing which two things to control, and having sensible targets for each type of image on your page.

Why image size matters

Images are usually the heaviest part of a web page. The bigger they are, the longer visitors wait, and the biggest image at the top of a page often decides how fast the page feels. Google measures this as Largest Contentful Paint (LCP), one of its Core Web Vitals, and treats 2.5 seconds or less as good. Smaller images are one of the easiest ways to get there, and they also save your visitors’ mobile data. For more on this, see how image compression helps page speed and SEO.

Two different sizes to control

  • Pixel dimensions are the width and height of the image, such as 1200 × 800. They decide how sharp the image looks and how much data the browser must process.
  • File size is how many kilobytes the file takes up. It decides how long the image takes to download.

Most oversized images have a dimensions problem first. A 4,000-pixel-wide photo displayed in a 800-pixel column is wasting most of its data, and no amount of compression fixes that as well as resizing does.

Rough targets by image type

Image typeTypical widthRough file size
Full-width hero or banner1,600–2,000 pxAbout 100–200 KB
Blog or article image800–1,200 pxAbout 50–150 KB
Product photo800–1,200 pxAbout 80–200 KB
Thumbnail or card image300–600 pxAbout 15–50 KB
Logo or iconAs small as it displaysUsually under 30 KB

Treat these as starting points rather than rules. A detailed photo needs more bytes than a simple graphic of the same size, and the right answer is whatever looks good and keeps your page fast. You can check with a tool such as Google’s PageSpeed Insights.

A simple workflow for every image

  1. Find out how big the image appears. If it fills a 700-pixel column, that is your reference width.
  2. Resize to about twice that width at most. A little extra helps the image stay sharp on high-density screens. Anything beyond that is wasted. Resizing is done in any image editor, your phone, or your CMS.
  3. Pick the right format. WebP is usually a good default for websites, JPG for photos when you need wide compatibility, and PNG for sharp graphics and transparency. Our format guide explains the differences.
  4. Compress it. Open the image compressor and use a moderate quality setting. If you want a specific size, the 100KB and 200KB pages let you set a target.
  5. Set width and height in your HTML. This lets the browser reserve space, so the page does not jump around as images load.
  6. Lazy-load images below the fold. Add loading='lazy' to images further down the page, but not to the main image at the top, because that one should load first.
  7. Test the page and see whether images are still flagged.

Common mistakes

  • Uploading camera originals. Straight-from-the-camera photos are far larger than any page needs.
  • Using one huge image everywhere. A banner image used as a small thumbnail still forces visitors to download the full file.
  • Lazy-loading the top image. It delays the part of the page visitors see first.
  • Saving photos as PNG. The file gets large with no visible benefit.
  • Over-compressing. If an image looks blocky or soft, raise the quality. This guide covers the common causes.
  • Forgetting alt text. It does not change file size, but it helps accessibility and search.

Frequently Asked Questions

What is a good image file size for a website?

For most content images, somewhere between 50 and 200 KB works well, depending on the image. Hero images can be a little larger and thumbnails much smaller. Check the page with a speed tool to confirm.

What dimensions should website images be?

Match the size at which the image is displayed, and go up to about twice that width at most for sharp results on high-density screens. A blog image in a 700-pixel column rarely needs to be wider than about 1,400 pixels.

Is WebP better than JPG for websites?

WebP files are often smaller at similar quality and all current major browsers support it, so it is a good default. JPG remains a safe choice when you need the widest compatibility. Read the full comparison.

Should I resize or compress my images first?

Resize first, then compress. Resizing removes data the page never uses, and compression then shrinks what is left.
